# Face Attendance Web 運用手順

## 新規セットアップ

空の新規フォルダへ展開し、READMEに従ってPython 3.12の仮想環境・依存ライブラリ・モデルを用意します。

- 架空データで試す：`python manage.py init --demo`
- 実データで新規開始：`python manage.py init`
- 起動：`python manage.py serve`
- モデル確認：`python manage.py check-models`

コマンドはそのフォルダの `.venv` のPythonで実行してください。デモ用初期設定は空のDBで1回だけ行います。

## ログイン

- 店舗端末：`http://127.0.0.1:8765/store`。店舗を選択し、同じ名称の再入力と共通パスワードでログイン。
- 店舗責任者：店舗の打刻画面の管理者ボタンから、本人の従業員ID・個人パスワードでログイン。
- 本社：`http://127.0.0.1:8765/hq`。従業員ID・個人パスワードでログイン。
- 個人・店舗共通パスワードは6文字以上。新規個人アカウントは123456。権限保持者は初回・リセット後に変更必須で、123456への変更不可。

デモのadminは000010001、hqは000010002、managerは000010003です。顔写真は初期登録されていません。

## 従業員と権限

従業員一覧で氏名・番号から検索し、詳細の「編集」で氏名・読み仮名を修正します。店舗責任者は申請、本社は直接確定です。写真更新・所属変更は別の申請で扱います。

新規登録には正面マスクなし・正面マスクありの2枚が必要です。店舗コード5桁＋識別番号4桁の番号を自動採番し、異動後も同じ番号を使います。

権限保持者一覧で、hq以上はmanager、adminはhqを付与・解除できます。managerは複数店舗を担当可能。adminへの昇格・adminからの降格は、サーバー停止中にコマンドで行います。

```powershell
.\.venv\Scripts\python.exe manage.py set-role --username [従業員ID] --role admin
.\.venv\Scripts\python.exe manage.py set-role --username [従業員ID] --role employee
```

角括弧部分は実際の9桁番号に置き換えます。対象・前後の権限を確認し、従業員番号を再入力して確定します。最後の有効なadminは降格不可です。権限変更後は対象者のログイン状態を無効化します。

## パスワードリセット

サーバー停止中に、サーバーを管理する人が実行します。

```powershell
.\.venv\Scripts\python.exe manage.py reset-password --username [従業員ID]
```

123456へ戻し、権限保持者は次回変更必須です。実行者と対象を操作ログに残します。利用停止を解除するコマンドではありません。

## 打刻・修正・業務連絡

本人認証・ライブネスが成功した場合に出退勤・休憩を記録します。受信した認証成功結果を5秒保持し、約4秒の開始間隔で更新します。打刻時にも新しい画像で同じ本人を確認します。

店舗責任者ホームは勤務中・休憩中の氏名と状態のみ。タップ・クリックで今回の勤務の出勤時刻・実働・休憩等を確認できます。

既存の勤務を修正する場合は勤怠一覧の該当行から操作します。本社は直接確定、店舗責任者は申請・承認を経て反映します。別の勤務と重なる修正は拒否します。

業務連絡は宛先・掲載期間を指定して投稿し、確認人数から個人別の確認状況を開きます。本文編集で確認済みを解除しません。

## 保存と接続

実行時データは通常 `data/attendance.db` に保存します。`ATTENDANCE_DB` で変更できます。停止時にdataを削除しないでください。

CSVは日次3時・30日保持、SQLiteは月次出力時に整合性確認付きでバックアップします。現用DBの勤怠履歴は自動削除しません。復元はadminが行い、事前退避と全ログイン無効化を伴います。

同一PCではlocalhostのURLを使用します。iPhone等の別端末でカメラを使うには信頼できるHTTPS接続が必要です。共有URLの公開範囲は利用環境に合わせて設定してください。

初期パスワードやデモの存在を前提とした検証用プロジェクトです。実際のカメラ・モデル精度と利用条件を確認してから運用を判断してください。

同じPCで複数のサーバーを同時起動する場合は、`serve --port 8766` のように使用ポートを指定します。`ATTENDANCE_DB` を設定済みの場合は、意図した保存先を指していることを確認してください。
