# 更新仕様 Ver.3

2026-11-16までに採用された更新を反映した実装仕様です。以前の資料は更新前の退避フォルダで参照できます。

## 所属・権限

部署00001〜00100、店舗00101〜99999。従業員番号は登録元コード5桁＋連番4桁、異動しても変更せず再利用しません。所属は店舗／部署から選びます。所属変更で自動昇格しません。

ロールはstore_manager、department_manager、area_manager、hq、admin。複数付与できます。エリアは店舗集合であり、area_managerの範囲は構成店舗から導出します。hq/adminがエリアを作成します。manager系はhq/admin、hqはadminが付与・解除し、admin変更はサーバーコマンド限定です。hq/adminは部署所属者に付与します。最終adminは解除できません。

新たなロール付与・再付与では123456へ戻し初回変更を要求、範囲だけの変更ではパスワードを維持します。すべての権限変更で対象のログインを無効化して記録します。パスワード6文字以上。

## 入口と端末

/store、/office、/adminの3入口。セッションCookieを分離します。本社部署は同じ有効パスワードなら複数選択可能。店舗共通と部署共通を分離、個別設定を優先します。名称再入力で設定ミスを防ぎます。共有パスワードの変更はhq/adminが申請し、別のhq/adminが承認します。平文は保存せず、対象端末のログインを失効させます。

顔認証・ライブネスはサーバーCPU、撮影・操作はブラウザ。最も大きい顔を対象にし、2番目が80%以上なら案内して認証しません。受信後5秒の認証チケット、約4秒間隔の再認証、打刻時の新フレーム照合。端末時刻と受信時刻の差が120秒以上なら却下。同一要求IDによる二重打刻を防ぎ、通信断時は結果照会します。

## 申請・承認

一覧と詳細に申請者と対象者（氏名・番号）を別々に表示します。差し戻し理由は画面内フォームで入力。編集再申請・承認前取消に対応します。年は4桁、月日時分秒は2桁で入力し、サーバーでも検証します。

|操作|直接操作|その他|
|---|---|---|
|新規登録・従業員情報修正・勤怠追加／修正・勤務取消／解除|hq/admin、担当範囲のarea_manager|店舗／部署責任者は申請|
|応援登録／変更／取消|本社・担当area_manager、対象日の打刻前|責任者は申請|
|所属異動|本社・担当area_manager、適用日前かつ対象日打刻前|その他は別人承認|
|写真更新・利用停止・利用再開|直接確定不可|別のhq/admin承認|
|有給|hq/admin|manager系は申請し本社承認|
|共用パスワード|直接確定不可|別のhq/admin承認|

写真は正面マスクなし／ありの2枚。申請前に氏名・番号・所属・プレビューを確認し、確認結果を画像内容と対象者へ結び付けます。写真更新承認時に2枚を一括差替えし、現用の旧画像・特徴量と申請用画像を削除します。バックアップの旧画像はその世代の削除まで残ります。履歴書のアップロードは実装しません。

## 勤怠・業務連絡

同日複数勤務、休憩、日付またぎ、応援先の打刻を記録。1勤務の総勤務時間24時間超は要確認、実際の修正は管理者が行います。担当ホームに現在勤務中・休憩中の氏名と状態、選択先に時刻・実働・累計休憩・総勤務を表示します。

業務連絡は複数宛先・全員選択・任意取り下げ・本文編集に対応。出勤／休憩終了後、未確認の新規連絡を表示し、確認ボタンで閉じます。編集で確認済みの人に再掲示しません。確認人数から全対象者の氏名・確認状況・確認日時（未確認は―）を表示します。

## 集計・有給

勤務開始日を勤務日とし、その勤務全体を開始月へ計上します。休日は実際の区間日付の土日祝。夜間22〜翌5時、残業は各勤務内の累計実働8時間超、休憩は区間から除き累計8時間にも含めません。日付をまたいでも残業累計をリセットせず、別勤務は合算して残業判定しません。

月次CSVは識別情報＋13指標：出勤日数、有給取得日数、総実働時間、通常日基本／深夜／残業／深夜残業、休日基本／深夜／残業／深夜残業、有給計上時間、過去月調整時間。8区分は排他的で合計が総実働。総実働に有給・休憩・別記の過去月調整を含めません。他の3明細CSVの列は維持します。

有給は店舗一般が全休のみ、直前の確定済み3暦月の実働÷実出勤日数（同日複数勤務は1日）、上限8時間。部署所属または権限保持者は半休4時間／全休8時間。承認時の算定根拠を保存します。実績なしは本社へ通知し、自動計上しません。手作業算定、給与金額、有給残日数は対象外です。

過去月修正は承認月の符号付き差分として別記し、控除できない残は翌月以降へ繰越します。確定後も元記録・申請履歴を保ち、修正は指定項目だけを最新記録に適用します。未退勤・要確認・処理待ちのある対象月を確定できません。

## 履歴・保守

操作履歴の検索とCSV、月次出力・確定・解除、バックアップ操作はhq/admin。復元とサーバー保存先等の設定はadmin。責任者は担当の勤怠と連絡確認状況を閲覧します。監査ログは期間削除を追加していません。

CSVを毎日3時に保存、未実行時は起動後補完、作成から30日で独立削除。SQLiteは月次出力時に年別フォルダへ保存。同じ対象月の手動上書きは確認後に検証成功した一時ファイルで置換し、失敗時に旧正常ファイルを維持。操作者・対象・成否を記録します。

SQLiteの旧年バックアップは年度完了、翌年12月31日到達、新しい年の正常バックアップ存在の条件で削除。現用DBの履歴は削除せず、年別運用DBへの切替もしません。復元はv3バックアップのみ、復元前退避し、ログインを無効化します。
