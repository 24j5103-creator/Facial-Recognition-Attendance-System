# 実装判断

所属データは既存の `stores` と `organizations` を組み合わせ、部署でも従来の勤怠・修正計上を再利用します。ロールは `role_grants` を正とし、ユーザーの代表ロールは表示用の補助です。エリアの担当店舗を重複付与せず集合から導出します。

過去月の確定値を後の修正で書き換えないよう、修正前の8時間区分を固定し、同月分の差分だけ区分計上します。過去月の差分は既存の計上・繰越台帳で承認月へ加えます。勤務開始月へ勤務全体を帰属させ、時間区分の休日は各区間の実際の日付で判定します。

有給の平均期間は取得月の直前3暦月とし、関係する所属の月次確定を必須とします。対象者の所属は取得日基準。承認時に算定し、根拠を保存します。実績のない場合、通知を別トランザクションで残してから入力エラーを返します。

日付は固定桁の数値入力に分割し、画面内の確認ダイアログを使用します。顔写真確認は、対象者情報と2枚の画像内容のハッシュに結び付けた一時トークンで検証します。

端末の複数部署パスワードは、同じ文字列を各部署の有効ハッシュへ照合します。ソルト付きハッシュ同士の等値比較は行いません。申請用パスワードは専用テーブルにハッシュのみを格納し、監査履歴・APIから除外します。変更対象の世代番号で競合を防ぎます。

既存のCPU認証・ライブネスモデル、5秒の認証受付、打刻要求の二重保存防止、月次確定・繰越、業務連絡の確認履歴を引き継ぎます。GPU構築・履歴書照合・給与金額・有給残日数は対象外です。
